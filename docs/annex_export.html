30.1 R formats

This section demonstrates how to export sits data to commonly used data structures in R, facilitating integration with other R packages.

30.1.1 Exporting time series data to sf

The sf package is the backbone of geospatial vector processing in R [1]. To export time series tibbles from sits to sf, the function sits_as_sf() creates an sf POINT object with the locations of each sample and includes the time_series column as a list. Each row in the sf object contains the time series associated to the sample.

# Export a sits tibble to sf
sf_obj <- sits_as_sf(samples_modis_ndvi)

30.1.2 Exporting data cubes to stars

The stars R package handles spatiotemporal arrays. It provides a general framework for working with raster and vector data. Data cubes in sits can be converted to stars objects using sits_as_stars(). By default, the stars object will be loaded in memory. This can result in heavy memory usage. To produce a stars.proxy object, users have to select a single date, since stars does not allow proxy objects to be created with two dimensions.

# create a data cube from a local set of TIFF files
# this is a cube with 23 instances and one band ("NDVI")
data_dir <- system.file("extdata/raster/mod13q1", package = "sits")
cube <- sits_cube(
    source = "BDC",
    collection = "MOD13Q1-6.1",
    data_dir = data_dir
)
stars_object <- sits_as_stars(cube)
# plot the first date of the stars object
plot(stars_object[,,,,1])

30.1.3 Exporting data cubes to terra

The terra package in R is a high-performance framework for spatial raster and vector data analysis. It was developed as the successor to the older raster package, offering a faster, more memory-efficient, and flexible API for working with geographic data. To export data cubes to terra, sits uses sits_as_terra() function which takes information about files, bands and dates in a data cube to produce an object of class SpatRasterDataset in terra. A SpatRasterDataset is an object that holds a collection of sub-datasets, where each sub-dataset is a SpatRaster sharing the same spatial extent and coordinate reference system. In terms of correspondence with sits, each sub-dataset holds all the bands of the data cube for a single time step. Therefore, the SpatRasterDataset will hold as many sub-datasets as there are time steps in the cube.

# create a data cube from a local set of TIFF files
# this is a cube with 23 instances and three bands ("NDVI", "EVI", "CLOUD")
data_dir <- system.file("extdata/sinop", package = "sitsdata")
cube <- sits_cube(
    source = "BDC",
    collection = "MOD13Q1-6.1",
    data_dir = data_dir
)
terra_object <- sits_as_terra(cube)
# show the contents of the SpatRasterDataset object

This section presents the available options for Python users to export sits data to various formats for further analysis and interoperability

30.2.1 Exporting time series and data cubes to xarray

The xarray library is a core tool for labeled multi-dimensional arrays in Python and it is widely used for handling various types of data, including time-series and Earth Observation Data Cubes. This section presents how to convert sits objects to xarray.

Exporting data cubes

Data cubes in sits can be converted to xarray objects using sits_as_xarray(). By default, the xarray object will be loaded in memory. This can result in heavy memory usage.

from pysits import sits_cube, sits_as_xarray
from pysits import r_package_dir

# Create a data cube from a local set of TIFF files
# this is a cube with 23 instances and one band ("NDVI")
data_dir = r_package_dir("extdata/raster/mod13q1", package = "sits")

# Load cube
cube = sits_cube(
    source = "BDC",
    collection = "MOD13Q1-6.1",
    data_dir = data_dir
)

# Transform to xarray
xcube = sits_as_xarray(cube)

30.3 Generic formats

This section describes formats that are not tied to a programming language. Data exported in these formats can be read by sits in both R and Python, and also by other software such as GIS packages, databases and data analysis libraries.

30.3.1 Exporting time series to Parquet

Apache Parquet is an open, column-oriented file format designed for efficient storage and retrieval of tabular data. Parquet files are compressed and can be read selectively by column, which makes them compact and fast to read. They are supported by many tools, including arrow in R, pandas, polars and geopandas in Python, DuckDB, GDAL and QGIS. For these reasons, Parquet is the recommended format in sits for saving and sharing time series. All training samples used in this book are stored as Parquet files in Hugging Face, as described in the chapter “Sharing and retrieving data with Hugging Face”.

Function sits_to_parquet() writes a sits tibble to a Parquet file. It has two parameters: data, the time series (tibble of class sits), and file, the full path of the file to be written, which must have the extension .parquet. The file uses a long layout: instead of storing each time series as a nested table, as sits does in memory, it has one row per sample and date. Each row holds the sample attributes (longitude, latitude, start_date, end_date, label and cube), a sample:id column that identifies the sample, an Index column with the date, and one column per band. A geometry column with the location of each sample is also added. Columns that do not follow the number of dates, such as predicted (classification results) and base_data, are kept nested.

The file footer contains two metadata blocks. The sits block stores the S3 class of the tibble, the order of the columns, the order of the bands and the names of the nested columns, so that the original tibble can be rebuilt exactly. The geo block follows the GeoParquet 1.1 specification, so that GDAL and QGIS read the file as a point layer. Both sits_to_parquet() and sits_from_parquet() require the arrow and jsonlite packages.

In the example below, we export the samples_modis_ndvi data set, which has 1,218 time series with the NDVI band, to a Parquet file. We then use arrow::read_parquet() to read the file as a plain table, to show the long layout.

Each sample now occupies as many rows as it has dates; the 1,218 samples of samples_modis_ndvi, with 12 dates each, become 14,616 rows. This layout is convenient for other tools. For example, analysts can filter the samples by label or date with SQL queries in DuckDB, or open the file in QGIS to view the locations of the samples.

Function sits_from_parquet() also reads Parquet files written by other programs, which have no sits metadata block. In this case, the file must have the columns longitude, latitude, start_date, end_date and label; files without them are refused. The class of the result is inferred from the columns: a column named Index is read as the time index, bands whose names start with EMB are read as embeddings (class embeddings), and a column named cluster indicates a set of clustered samples (class sits_cluster). Files written by a different version of the layout are read, with a warning.

The file parameter can also be an HTTP or HTTPS URL. In this case, sits_from_parquet() first reads the file footer to check that it holds a sits sample set, and refuses the file before transferring any data if it does not. It then reports the size of the file and downloads it to a temporary location. The server must accept byte-range requests, as Hugging Face does. In the example below, we read the deforestation samples for Rondonia directly from their Hugging Face URL. The result is a sits tibble with 6,007 time series. The parameter timeout sets the number of seconds each request may take. For files stored in Hugging Face, sits_from_hf() is a simpler alternative, since it only requires the name of the repository and of the file.

  • R
  • Python
# read samples directly from a URL
samples_rondonia <- sits_from_parquet(
    file = "https://huggingface.co/datasets/e-sensing/samples_book/resolve/main/samples_deforestation_rondonia.parquet"
)
# read samples directly from a URL
samples_rondonia = sits_from_parquet(
    file = "https://huggingface.co/datasets/e-sensing/samples_book/resolve/main/samples_deforestation_rondonia.parquet"
)
